# Ferrite v0.3.2 implementation plan

> **Status:** Active. Math preview and `serde_norway` landed 2026-11-18. `notify` 8.2.2 is on branch `notify-8` and is not merged here. Wave 1 left is large-file memory and the cosmetic bundle, plus three earlier items already on `0.3.2-experimental`.
> **Date:** 2026-11-18. Model split corrected the same day after math shipped.
> **Models:** Grok 4.7 high takes a whole specified PRD in one session. Fable only for the design jobs that still have no PRD.
> **Feature list:** [ROADMAP.md](../ROADMAP.md) § v0.3.2. This file is the order and the model split. It does not replace the PRDs.

v0.3.1 shipped on 2026-11-11. The v0.3.2 heading in the roadmap is several releases of work. Wave 1 is the set to finish before calling a tag. Waves 2 and 3 stay in order so later work does not freeze an API or a parser that the earlier wave is about to change.

## Rules

- One session is one parent task. Do not combine a dependency bump with a feature.
- `serde_norway` and `notify` 8.2.2 each landed on their own branch. Stay off notify 9. Stay off `noyalib` and `serde_yml`.
- Math is on comrak 0.22. comrak 1.0 (published 2026-11-17) is its own branch and re-checks dollar math, then HTML phase 3.
- Large-file step 1 before step 2. Step 2 before the FerriteEditor crate publishes a buffer type. Math has already landed, so step 2 should include whatever the preview reads.
- Rendered list Tab and copy-as-text edit the same walker math just landed in. Give each its own session and read the new placement before changing it.
- **Model rule, corrected 2026-11-18.** A PRD that names the pipeline, the files, and the tests is one Grok 4.7 high session, including a new raster path and the rendered walker. Math proved that. Fable is for work that is still a design problem with no PRD: the FerriteEditor and Mermaid crate boundaries, and the Mermaid layout research v0.3.1 already deferred (subgraph hierarchy, dense parity). If a Grok session on one of those stalls, that is the escalation.
