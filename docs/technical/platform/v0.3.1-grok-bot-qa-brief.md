# v0.3.1 QA brief for an autonomous agent (Grok Bot, Linux cloud desktop)

This is the hand-off document for an AI agent with its own Linux desktop, terminal
and browser (Grok Bot or similar) to **build Ferrite from the `0.3.1-experimental`
branch and run as much of the v0.3.1 manual test suite as it can**, then return a
written report. It exists because the maintainer cannot run the full manual pass
by hand right now.

Everything the agent needs is in the repository once it has cloned the branch.
The rest of this file is written **to the agent**.

---

## 0. Mission, scope, rules

**Mission.** Build the `0.3.1-experimental` branch of
<https://github.com/OlaProeis/Ferrite> in release mode on your Linux computer, run
the automated gate, then execute the manual QA checklists against the real GUI
(you can click, type and take screenshots on your desktop). Produce one report
file plus screenshots and hand them back in the conversation.

**You are a tester, not a fixer.**

- Do **not** modify source code, do **not** commit, push, open PRs or GitHub
  issues. Your only deliverables are the report and the evidence files.
- Do **not** work around a crash or a wrong result to make a row pass. A crash
  is a `FAIL`, always. Release builds use `panic = "abort"`, so a panic simply
  kills the process — that is the signal.
- If a row needs something you cannot do (Windows-only, macOS-only, network
  blocked, hardware), mark it `SKIPPED (<reason>)` and move on. Never invent a
  result.
- If you get stuck on a step for more than ~4 attempts, mark the row `BLOCKED`
  with what you observed and continue with the next row.
- Work inside `/workspace/ferrite-qa/`. Keep screenshots and logs there.

**Stale notes you must override.** Some checklist rows say things like
*"KNOWN CRASH until PRD §5.2 lands"*, *"KNOWN BUG until PRD §5.6 lands"* or
*"KNOWN GAP (#186 PRD)"*. Those PRD tasks have **all landed** on this branch.
Treat every such note as obsolete: the row is now expected to **PASS**, and a
crash or wrong result is a real `FAIL`. Specifically, rows **4b, 15, 16, 21,
25b and 38** of the minimal test are now expected to pass.

## 1. Environment setup (Linux)

Run these in a terminal. Debian/Ubuntu commands shown; adapt for other distros.

```bash
# 1. System build deps (same list as the project's CI)
sudo apt-get update
sudo apt-get install -y build-essential pkg-config git curl \
  libgtk-3-dev libwebkit2gtk-4.1-dev libsoup-3.0-dev \
  libxcb-shape0-dev libxcb-xfixes0-dev libfontconfig1-dev \
  libxkbcommon-dev libssl-dev

# 2. QA helper tools: clipboard, hex dump, fonts for emoji / CJK rows
sudo apt-get install -y xclip wl-clipboard xxd file python3 \
  fonts-noto-color-emoji fonts-noto-cjk

# 3. Rust (toolchain >= 1.92 is required by Cargo.toml rust-version)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"
rustup update stable
rustc --version   # must be >= 1.92

# 4. Clone the branch
mkdir -p /workspace/ferrite-qa && cd /workspace/ferrite-qa
git clone --branch 0.3.1-experimental https://github.com/OlaProeis/Ferrite.git ferrite
cd ferrite
git log -1 --oneline        # record this commit hash in the report
```

### Build

```bash
cd /workspace/ferrite-qa/ferrite
cargo build --release 2>&1 | tee ../build-release.log
ls -la target/release/ferrite
./target/release/ferrite --version
```

A release build takes a while (10–25 min on a modest VM). Use the time to read the
checklists listed in §3.

### Running the app for GUI tests

Always run from a terminal so you capture logs and the exit code:

```bash
cd /workspace/ferrite-qa/ferrite
mkdir -p ../logs ../shots
./target/release/ferrite --log-level debug 2>&1 | tee ../logs/run-$(date +%H%M%S).log
```

- If the window does not appear or OpenGL fails, retry with
  `LIBGL_ALWAYS_SOFTWARE=1` and/or `WINIT_UNIX_BACKEND=x11` in the environment.
- Settings/session live in `~/.config/ferrite/`. For a clean first launch move it
  aside once: `mv ~/.config/ferrite ~/.config/ferrite.bak-$(date +%s)`.
- Open a specific file: `./target/release/ferrite /path/to/file.md`.
  Open the repo as a workspace: `./target/release/ferrite /workspace/ferrite-qa/ferrite`.
- Useful CLI flags: `--new-instance`, `--log-level debug|info|warn|error|off`, `--version`.
- Take a screenshot for every `FAIL` and for the key `PASS` rows in Tier 1.
  Name them `<ROW-ID>-<pass|fail>.png` in `/workspace/ferrite-qa/shots/`.
