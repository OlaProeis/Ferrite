# v0.3.1 Minimal Release Test — 0.3.0 → 0.3.1 in ~60 minutes

**Purpose.** The full pass ([`v0.3.1-total-test.md`](./v0.3.1-total-test.md), 150+ rows) is the
ideal. This document is the *realistic* one: the smallest set of manual checks that
catches the bugs that would actually hurt a 0.3.0 user upgrading to 0.3.1. Everything
here is ordered by **blast radius** — if you run out of time, stop after Tier 1 and
you have still covered every known crash / data-loss surface.

> **Rules:** `[ ]` not run · `[x]` pass · write **FAIL** inline and add an `ISS-n` row at
> the bottom. Use a **release** build (`cargo build --release`; release uses
> `panic = "abort"`, so any panic you trigger kills the app — that *is* the test).
> Primary platform: **Windows**. Rows marked `(skip-ok)` can be skipped without blocking
> the tag.

Automated gate already run (2026-09-08): `cargo test` → **1,958 passed / 0 failed**.
